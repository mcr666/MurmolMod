## Hard Constraints
- All Feral Form logic must be implemented in object-oriented manner with pure data classes and behavior集中 in Manager
- Feral form state must be stored in PlayerVariables NBT data using feralFormId instead of FERAL_TYPE attribute
- Procedure files related to Feral Form (Tf*Procedure, Ifferal*Procedure) must be deleted
- AstralCruse mod must be integrated directly into MurmolMod with feral_type logic replaced by FeralFormManager
- Astral tail rendering from armor must be handled as an independent module separate from Feral Form system
- Output JAR filename must match modId and version from neoforge.mods.toml (format: {modId}-{version}.jar)
- 编译成功后 JAR 只留在 build/libs，不复制替换到 .minecraft mods、不启动游戏（用户自己处理）
- 1.21.1 附魔是动态注册表：BuiltInRegistries 无 ENCHANTMENT 字段；拿附魔 Holder 需 registryAccess().lookupOrThrow(Registries.ENCHANTMENT)，创造栏上下文用 ItemDisplayParameters 的 parameters.holders()（HolderLookup.Provider），勿误用 tabData
- JEI integration must be a soft dependency (compileOnly + runtimeOnly, not packed into JAR, no mods.toml dependency)
- Patchouli 是必要前置依赖（mods.toml type="required"，无版本限制，compileOnly + runtimeOnly 不打进 JAR）
- Compilation requires running .\gradlew.bat --no-daemon build with sandbox disabled
- Edit changes must be confirmed by user before compiling

## Engineering Conventions
- Feral Form classes (e.g., HumanForm, LuohongForm) extend FeralForm base class and contain only data in constructor
- New Feral Forms are added by creating XxxForm class and registering in FeralForms registry
- All Feral Form behavior (state management, attribute modifiers, transformation流程) is centralized in FeralFormManager
- Client-side rendering for Feral Forms is handled by FeralFormRenderer with model layers registered in FeralFormModels
- Model fields must be accessed via reflection using getDeclaredField() + setAccessible(true) to handle private final fields
- Player model offset is controlled via BODY_Y_OFFSET (1 model unit = 1/16格) in FeralFormRenderer, with additional CROUCH_Y_OFFSET for潜行状态
- JEI plugins are registered via @JeiPlugin and placed in net.mcr.murmol.jei package
- JEI recipe categories for Feral Form transformations use 2×2 input grid + arrow + output slot layout, with catalyst item as 幻星秘典 (the_astral_tome)
- Human form transformation recipe uses 水桶 + 不死图腾 + 绿宝石 + 任意船 (minecraft:boats tag) as input materials
- Recipe ingredient detection must be order-independent (count-based id matching)
- Game commands are implemented in MurmolCommands class with permission level 2 (cheat/OP required by default)
- 形态切换命令/murmol tf <form> uses Tab completion from FeralForms.all() and triggers full transformation流程 via FeralFormManager.transformFromItem
- 手册条目解锁/锁定命令：/murmol book unlock(lock) <目标选择器> <条目|all>，条目参数支持Tab补全（all+各形态id），操作进度的impossible criteria实现与残页解锁机制共用同一进度
- Animation state transitions use 迟滞双阈值判定：起走需 limbSwingAmount > 0.02，停走需 < 0.004，避免边界值徘徊导致频繁状态切换
- Tail animations crossfade:行走/待机按 4 tick 渐进权重混合（idle×(1-w) + walk×w，walk 采样再乘 limbSwingAmount），状态切换阈值 limbSwingAmount > 0.01，避免硬切丢失过渡；行走相位存于 TailBlend 仅行走时推进，淡出期间冻结相位避免停止后多踏两步
- FeralForm.animateCoreBones（默认 true）：烘焙姿态形态（silkmoth 设 false）走 applyBakedPoseExtras——resetPose 还原全部部件到 Blockbench 烘焙姿态，但先抓取并写回手臂/头原版旋转（动画无关关键帧的骨骼保留原版动画，有关关键帧的骨骼如腿用 moth_walk 自定义动画），翅膀按 wings_flying(飞行)/wings_idle(其余) 叠加；silkmoth_anim.json 为 anim2 版（仅含 moth_walk/tail_idle/tail_walk/wings_idle/wings_flying）
- 月蛾 biped_* 附加骨骼：FeralFormModels.bakeBodyModel 从根 body 提取（不进包装模型）存 EXTRA_PARTS，FeralFormRenderer 额外渲染（applyBipedAnimation + 同步 shift/offsetScale/crouch 偏移），moth_walk 通道 ×limbSwingAmount 驱动，与尾巴共用 TailBlend 冻结相位
- 各形态动画均为专属文件 assets/murmol/player_animations/<form>_anim.json（FeralForm.setAnimationFile 指定），human 无专属文件时回退全局 astral_cruse:player_animations/feral_anim.json；尾部动画整合为文件内 tail_idle/tail_walk，由 FeralFormRenderer.applyTailAnimation 按动画定义的骨骼名（如 TailPrimary/bep1）在躯干子树查找
- JEI 开发依赖版本为 19.16.4.183（与用户 mods 文件夹一致，兼容 NeoForge 21.1.232）；19.54+ 要求 NeoForge 21.1.238 会导致 dev 运行崩溃
- 旧版 JEI（19.16.x）的 IRecipeCategory 要求实现 getBackground()（新版已移除该抽象方法）；VSCode JDT 运行时 classpath 来自 Gradle 同步缓存，改 build.gradle 后必须 Refresh Gradle Project 才生效
- 原版行走动画相位单位：animateWalk 用 limbSwing × 0.6662 × 50 毫秒 = ×0.03331 秒（勿误用 0.79944 秒，会快 24 倍导致动画抖动）
- 模型项目 bin/ 目录是 VSCode Java 插件（Eclipse JDT）的开发运行时输出目录（dev 启动参数 mod coordinates 指向 bin\main），严禁删除；报 "Resource already exists on disk" 用 Java: Clean Java Language Server Workspace 解决，删 bin\main 会导致 FML 启动崩溃 Invalid paths argument
- 用户开发流程：在 VSCode 里直接用调试配置 runClient（游戏目录 run/，日志 run/logs/latest.log），同时保留 build/libs JAR 发布流程
- 苔叶兽环境条件属性：所处位置天空光=0 判定为洞穴（getBrightness(LightLayer.SKY)==0），洞穴加成 modifier id murmol:tf_cave（移速+0.01/跳跃+0.2/挖掘+1），地面 murmol:tf_surface（移速-0.05）；clearModifiers 需一并清除这两个 id
- 帕秋莉手册：显示一组物品用 patchouli:relations（关联的是条目id，物品条目不可用时用 spotlight 逗号分隔列表）；文本换行用 $(br)、$(br2)
- 四形态手册统一为四页格式（spotlight 描述 / patchouli:crafting 配方（替代 relations，避免物品id当条目id报 Could not find entry）/ 属性 / 正文）；结缘之祭物后不加合成说明文字
- 配置项均在 "client" 分组：modifyTitleScreen（主菜单全景+按钮+音乐合并项，默认关）、showHiddenFeralArm（默认关）、renderBiomeParticles（murmol 群系环境粒子开关，默认开）
- 群系环境粒子拦截在 AmbientParticleSettings.canSpawn（HEAD cancellable，按粒子 namespace==murmol 过滤），勿混入 ClientLevel.doAnimateTick
- 状态机/采样约定：附加骨骼采样秒数必须经 animationTime() 循环取模（超过动画长度未取模恒为末帧导致动画"不动"）；月蛾按空格（跳跃输入）即切 wings_flying，无需等离地
- FeralForm 开关：modifiesHitbox（silkmoth=false 不改碰撞箱/眼高）、canWearChestArmor（silkmoth=true 允许胸甲）、enableFirstPersonArm（silkmoth=true，其余三形态 disable）
- 月蛾环境机制：露天（天空光>0）白天 -0.05移速/-4生命、夜晚 +0.05/+4，黑暗处无增减（FeralFormManager.updateSilkmothEnvironmentModifiers，modifier id murmol:tf_silkmoth_day/night）；月蛾白天睡觉由 CanPlayerSleepEvent 处理器实现
- 量子态附魔（murmol:quantum_state，1级，armor 槽）：佩戴者变形时护甲不脱落（FeralFormManager 掉落判定豁免）；获取=图书管理员4级交易12绿宝石+两个mod结构宝箱5%奖池
- 狛犬（komainu）石像状态：静止5秒触发，抗性I、苔石/磐座贴图、潜行动画锁定、2格外怪物不可选取（TargetingConditionsMixin）；站在磐座（murmol:banza，4/16高苔石基座）上右键立即石化且回血；进出喷石头粒子
- 芒果丛（murmol:mango_bush）：四阶段 cross 方块，甜浆果丛行为克隆，芒果种植；贴图已本地化 textures/block/mango_bush_stage0~3.png（用户将自行修改）
- 生产环境启动无声中断（无 ERROR/无 crash report/无 hs_err，进程在 Mixin 混入阶段戛然而止）时优先查：启动器弹窗文本、debug.log 最后一条 Mixing/Verification 记录、对比上午成功运行的 git/JAR 差异二分新增 Mixin
- @Redirect 勿指向被反编译进 lambda 的原版逻辑（如 1.21.1 白天睡觉判定在 ServerPlayer.lambda$startSleepInBed$13，Player.startSleepInBed 方法体内无 isDay）；月蛾白天睡觉改用 NeoForge 原生 CanPlayerSleepEvent（vanillaProblem==NOT_POSSIBLE_NOW 时 setProblem(null)），SilkmothSleepMixin 已删除
- javap 分析原版字节码：mojmap 类在 ~/.gradle/caches/neoformruntime/intermediate_results/recompile_*_output.jar，NeoForge 类在 neoforge-*-universal.jar（仅含 neoforge 包）；1.21.1 无 SleepingTimeCheck 事件（Forge 的），对应替代是 CanPlayerSleepEvent
- 生成 JAR 已升版 2.1.2（build.gradle + neoforge.mods.toml 同步改）
- silkmoth 已于 2026-09-25 汉化改名为「月蛾」（zh_cn.json + form_silkmoth.json 手册，英文名 silkmoth 不变）
- FeralBedrockPlayerAnimator 中仍有临时诊断日志（debugPose 的 [feral-debug2] 与 animationsForFile 的 [feral-debug] loaded 行），问题定位完成后需删除
- Tail animation walkTime calculation uses limbSwing × 0.03331 (seconds) to match vanilla animateWalk phase conversion
- Blockbench 导出的 {"post":[...],"lerp_mode":"catmullrom"} 帧格式由 FrameValue.read 兼容（取 post、忽略 lerp_mode 按线性插值）；1.21.1 renderToBuffer 签名是 (PoseStack, VertexConsumer, int light, int overlay, int color)，旧导出的 4-float 颜色签名会编译失败

## Lessons Learned
- Static final fields in @Mixin(Minecraft.class) cause DeferredHolder binding failure during class initialization; use lazy initialization in methods instead
- NeoForge 21.1 has no neoforge:partial_nbt ingredient (removed in 1.21); use {"type":"neoforge:components","items":[],"components":{"minecraft:custom_data":{}},"strict":false} to match CUSTOM_DATA component content
- 1.21.2+ recipe format uses pure string简写 which may cause compatibility issues; ensure all recipe JSONs use compatible format for NeoForge 21.1
- Blockbench-exported animation frames with {"post": [...], "lerp_mode": "catmullrom"} format cause parsing exceptions; must handle lerp_mode (treated as linear interpolation) to prevent animation file loading failure
- 历史测试代码可能导致头部旋转被丢弃，需检查并移除影响特定形态动画通道的冗余代码
- Using limbSwing × 0.79944 for walkTime caused tail_walk animation to cycle 24x faster than normal, resulting in constant shaking during movement
